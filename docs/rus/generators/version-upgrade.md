# Обновление версии Minecraft

[English](../../eng/generators/version-upgrade.md) · [Документация](../README.md)

Руководство описывает перенос ядра на другую версию Minecraft. Сейчас Vitis поддерживает 1.21.4. Выбор новых данных для генерации требует соответствующих изменений кода сервера.

## Подготовка

Используйте отдельную ветку или копию исходников. Сохраните сгенерированные файлы, эталонные данные тестов и миры для восстановления. Зафиксируйте результаты сборки и тестов; изучите [известные проблемы](../status.md).

По официальным данным и исходникам новой версии проверьте протокол, DataVersion, формат датапака, версию Java, таблицы имён, реестры и формат пакетов. [Генерация](README.md) готовит официальный JAR, переименованный JAR и Java-исходники. Если нужен другой JDK или формат исходников, обновите и закрепите требования инструментов.

## Генерация и проверка

Для текущей версии, Linux (Bash):

```bash
make generate MC_VERSION=1.21.4
```

Windows (PowerShell 7.2+):

```powershell
pwsh -NoProfile -File .\scripts\windows\update_version.ps1 -Version 1.21.4
```

После адаптации генераторов укажите новую версию через `MC_VERSION` на Linux или `-Version` на Windows. По умолчанию используется 1.21.4. Прямой Linux-скрипт `./scripts/linux/update_version.sh <version>` принимает тот же аргумент.

Проверьте код выхода и восстановление после ошибки. Изучите `source.lock`, контрольные суммы, изменения кода и тестовых данных. Повторная генерация с одинаковыми входными данными должна давать одинаковые файлы. Разберите неожиданные изменения порядка, идентификаторов и типов.

## Изменения ядра

- Обновите [константы протокола](../../../internal/protocol/state.go), [формат датапака](../../../internal/datapack/manager.go) и остальные зависимости от версии. Проверьте подготовку ресурсов из нового официального JAR при первом запуске.
- Генератор обновляет [идентификаторы сервера](../../../internal/protocol/packetid/) и совместимые константы вместе. После генерации запустите его с `--check`.
- Обновите поля пакетов, регистрацию состояний и направлений, этапы входа и настройки клиента, проверки размеров.
- Проверьте ID реестров, числовые типы NBT, теги и объявления известных пакетов ресурсов. Добавьте обработку новых имён реестров.
- Сверьте состояния блоков, компоненты, рецепты, добычу, метаданные сущностей и признаки генерации с новой версией.
- Определите допустимые DataVersion мира. Сохраните резервное копирование и отказ открытия несовместимого мира; изменение константы не переносит данные.
- Обновите экспортёры, эталонные данные тестов и обе версии документации, включая таблицу возможностей.

Поиск зависимостей от версии из корня репозитория. Linux (Bash):

```bash
rg -n '1\.21\.4|769|4189|CurrentPackFormat|go:generate' cmd internal scripts configs docs README*.md
go build ./...
make verify
```

Windows (PowerShell 7.2+):

```powershell
Get-ChildItem cmd,internal,scripts,configs,docs -Recurse -File | Select-String -Pattern '1\.21\.4|769|4189|CurrentPackFormat|go:generate'
Get-ChildItem README*.md | Select-String -Pattern '1\.21\.4|769|4189|CurrentPackFormat|go:generate'
go build ./...
pwsh -NoProfile -File .\scripts\windows\verify.ps1
```

Проверяйте каждое совпадение перед заменой.

## Проверка результата

Проверьте порядок этапов, шифрование, сжатие, синхронизацию реестров с известным клиенту встроенным пакетом и без него, некорректные пакеты и уникальность ID внутри каждого состояния и направления. Подключите клиент новой версии: проверьте вход, чанки, инвентарь, игровые механики, сохранение, повторное подключение и остановку.

Сравните сгенерированные чанки с эталоном и повторно откройте временный существующий мир. Зафиксируйте оставшиеся ошибки тестов.

См. также: [идентификаторы пакетов](../packets/packet-ids.md), [реестры](../registry/overview.md), [тестирование](../testing.md).
