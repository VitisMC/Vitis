# Добавление команды, пакета или механики

[English](../eng/extending.md) · [Документация](README.md)

## Команда

Начните с [определений команд](../../internal/command/) и [Command/Context](../../internal/command/command.go). Пример регистрации:

```go
package example

import "github.com/vitismc/vitis/internal/command"

// RegisterExample registers a bounded, permission-checked console/player command.
func RegisterExample(registry *command.Registry) error {
    return registry.Register(&command.Command{
        Name:            "example",
        Description:     "Replies with a fixed message",
        Usage:           "/example",
        PermissionLevel: 2,
        Execute: func(ctx *command.Context) error {
            if ctx.ArgCount() != 0 {
                ctx.ReplyError("Usage: /example")
                return nil
            }
            ctx.Reply("Example command is active")
            return nil
        },
    })
}
```

Пример оформлен как самостоятельный пакет. В ядре добавляйте команды в существующий пакет, используя его функции создания и регистрации.

Подключите команду к регистрации и обработайте ошибки. При необходимости добавьте описание аргументов и автодополнение. Обработчик проверяет аргументы и вызывает игровую подсистему; генерация мира и дисковые операции выполняются отдельно.

Изменения мира проводите через существующий обработчик команд и очередь тика. Обрабатывайте переполнение очереди. Проверяйте права, неверные аргументы, запуск от консоли и игрока, изменение состояния и передачу ошибок. Проверьте справку и `DeclareCommands`, затем обновите [каталог команд](commands.md) на обоих языках.

## Сетевой пакет

1. Проверьте состояние, направление, ID и формат пакета по данным и исходникам нужной версии Minecraft.
2. Добавьте тип в соответствующий пакет протокола. Реализуйте `ID`, `Decode` и `Encode` с проверкой границ и длин.
3. Зарегистрируйте кодек в [состояниях протокола](../../internal/protocol/states/).
4. Добавьте обработчик сессии. Если пакет намеренно принимается без действий, укажите причину в соответствующей политике.
5. Проверяйте состояние сессии, игрока и допустимость действия. При необходимости ставьте изменение мира в очередь. Сохраняйте порядок ответов при согласовании параметров и смене состояний.
6. Проверяйте кодирование и декодирование, обрезанные данные, неверные длины, лишние байты, недопустимые состояния и игровые результаты. Для декодеров клиентских данных при необходимости используйте фаззинг.

ID берётся из протокола, а не из позиции в произвольном списке. Различие генерируемых и используемых сервером ID описано в [идентификаторах пакетов](packets/packet-ids.md).

## Механика

Найдите подходящий обработчик в [карте игровых подсистем](gameplay.md). Разместите правила в существующем пакете ядра; отдельный адаптер добавляйте при необходимости.

Определите, какая горутина владеет состоянием, как обрабатывается отказ очереди и что происходит при повторном входе, смерти игрока или выгрузке мира. Не храните ссылки на игрока, мир или сессию после завершения их жизненного цикла.

Подключите механику к действию или тику. Синхронизируйте состояние клиента, отмечайте изменения для сохранения и реализуйте запись и загрузку. Проверяйте обычное поведение, недопустимые запросы, отключение, отмену и восстановление состояния.

## Проверка результата

Проверьте действие через обработчик сервера, обновление клиента и сохранение данных. Обновите [возможности](status.md) и связанные руководства на обоих языках. Обязательные проверки описаны в [тестировании](testing.md).
