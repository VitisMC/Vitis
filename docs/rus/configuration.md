## Загрузка и значения по умолчанию

Флаг `-config` задаёт путь к конфигурации; по умолчанию это `configs/vitis.yaml` относительно рабочего каталога. Отсутствующий файл создаётся при запуске, существующий сохраняется. Неизвестные YAML-ключи отклоняются. Пропущенные параметры получают значения из [Default](../../internal/config/defaults.go), затем конфигурация проходит [проверку](../../internal/config/validate.go).

В таблице указаны **встроенные значения по умолчанию**. Отличия примера YAML перечислены ниже. `P = max(2, GOMAXPROCS(0))`, `W = max(2, floor(2 × P / 3))`. Длительность тика зависит от фактической частоты работы мира.

## Изменение во время работы

Сервер проверяет файл каждые 500 мс и ждёт 150 мс после изменения перед перезагрузкой. Если новые значения некорректны или изменение запрещено, действуют прежние настройки.

| Код | Поведение |
| --- | --- |
| L | Применяется без перезапуска. |
| R | Изменение во время работы отклоняется; нужен перезапуск. |
| S | Читается при старте. Файл может быть принят при перезагрузке, но значение начнёт действовать только после перезапуска. |
| U | Настройка не используется сервером. |
| U/R | Не используется; изменение во время работы также отклоняется. |

`/reload` обновляет датапаки. YAML отслеживается отдельно. Настройки списка игроков хранятся в другом файле: см. [ресурсы](resources.md).

## Отличия примера YAML

[configs/vitis.example.yaml](../../configs/vitis.example.yaml) — production-пример: проверка аккаунтов, Survival и стандартные дальности `10/6`. Локальный `configs/vitis.yaml` — рабочая конфигурация; она исключена из Git.

Без проверки аккаунтов клиент может представиться чужим именем. Для публичного сервера включайте `online_mode`. Смена режима меняет UUID; данные игроков и списки доступа автоматически не переносятся.

Рабочая конфигурация может увеличивать дальности и лимит отправки чанков. Начинайте со встроенных значений и увеличивайте их после проверки нагрузки; см. [установку](getting-started.md).
