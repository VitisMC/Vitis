# Хранение миров, резервные копии и восстановление

[English](../eng/storage.md) · [Документация](README.md)

## Формат и совместимость

`world.default_world_name` задаёт каталог мира. Структура:

```text
world/
  level.dat
  playerdata/
  region/
  entities/
  poi/
  datapacks/
  vanilla/<version>/
  DIM-1/                 Регионы, сущности и точки интереса Нижнего мира
  DIM1/                  Регионы, сущности и точки интереса Края
  dimensions/<namespace>/<path>/   Дополнительные измерения
```

Чанки хранятся в Anvil `.mca`, данные игроков и метаданные — в NBT. У существующего `level.dat` должна быть DataVersion **4189**. Другие версии отклоняются; автоматической миграции DataFixer нет. Начальное значение генерации и настройки существующего мира берутся из метаданных.

При записи регионов сохраняются поддерживаемые данные и неизвестные поля. Перед открытием ценного мира проверьте работу сервера на независимой копии.

## Сохранение

Тик мира создаёт ограниченное число неизменяемых снимков чанков. Фоновые задачи записывают их в регионы и подтверждают успешную запись. Если чанк изменился после создания снимка, он остаётся помеченным для сохранения. Интервалы и лимиты описаны в [конфигурации](configuration.md).

Данные игроков сохраняются периодически по `world.autosave_interval_ticks`, при событиях жизненного цикла и остановке сервера. Ограниченный writer применяет упорядоченные снимки и сохраняет ожидающие задачи при переполнении очереди. Playerdata содержит текущее измерение, cooldown портала, измерение личного spawn, инвентарь и выбранный слот панели. Проверяйте ошибки записи и завершения: SIGKILL, заполненный диск и прерывание записи могут привести к потере данных.

## Автоматическая копия первого открытия

При `backup_world: true` сервер копирует существующий мир в соседний `<world>.vitis-backup` до изменения его содержимого. Копия создаётся во временном каталоге, затем устанавливается на место. Неподдерживаемые типы файлов, включая символические ссылки, вызывают ошибку.

Готовая копия **никогда не обновляется**. Она сохраняет состояние первого открытия. Проверка метаданных и резервное копирование выполняются до установки ресурсов. Для нового мира, содержащего только проверенный встроенный пакет, копия не создаётся.

Копия, сделанная до первого переноса ресурсов, не содержит позднее установленного пакета. Сохраняйте исходник в `.mcdata` или после остановки сервера создайте новую полную копию.

## Создание актуальной копии

1. Выполните `stop`, дождитесь успешного выхода и проверьте ошибки.
2. Скопируйте весь каталог мира: измерения, метаданные, датапаки, `vanilla/<version>/`, данные игроков и прогресс прегенерации.
3. Отдельно сохраните YAML, JSON списков доступа и шаблоны списка игроков. Ограничьте доступ к этим файлам.
4. Храните копию вне рабочего мира и проверьте восстановление.

Linux, после остановки сервера:

```bash
mkdir -p /tmp/vitis-backups
tar -czf "/tmp/vitis-backups/world-$(date -u +%Y%m%dT%H%M%SZ).tar.gz" world
```

Windows (PowerShell), после остановки сервера:

```powershell
$backupRoot = Join-Path $env:TEMP "vitis-backups"
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
$stamp = [DateTime]::UtcNow.ToString("yyyyMMddTHHmmssfffffffZ")
Copy-Item -LiteralPath world -Destination (Join-Path $backupRoot "world-$stamp") -Recurse -Force
```

Замените `world` на настроенный каталог. Для настоящих резервных копий используйте постоянное хранилище; `/tmp` и `$env:TEMP` здесь служат примерами. Копирование регионов работающего мира не обеспечивает согласованную копию.

## Восстановление

Остановите Vitis и сохраните проблемный мир отдельно. Восстановите проверенную полную копию в пустой каталог, сохранив структуру и конфигурацию. Проверьте DataVersion и версию ресурсов. После запуска изучите логи до допуска игроков. Не объединяйте отдельные регионы с работающим миром и не меняйте DataVersion вручную.

Смена режима проверки аккаунтов меняет UUID. Данные игроков, операторов, блокировок и белого списка автоматически не переносятся.
