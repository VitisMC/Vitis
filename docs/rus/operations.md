# Эксплуатация сервера

[English](../eng/operations.md) · [Документация](README.md)

## Рабочий каталог и файлы

Запускайте бинарник из доступного для записи каталога сервера. `-config` задаёт путь только к YAML-конфигурации. Ресурсы, `configs/tab.yaml`, `ops.json`, `whitelist.json`, `banned-players.json` и `banned-ips.json` используют рабочий каталог процесса. См. [установку](getting-started.md).

Отсутствующие списки доступа считаются пустыми. Нечитаемый или повреждённый файл блокирует запуск. Перед публикацией отчёта об ошибке удалите пароли, списки операторов и личные данные игроков.

## Консоль и права

В консоли команды вводятся без `/`: `help`, `list`, `op PlayerName`, `stop`. В игре используется `/`. Консоль и RCON имеют административные права, но команды, которым нужны позиция или инвентарь игрока, требуют выполнения от игрока.

Для первого оператора подключите игрока и выполните `op PlayerName` в консоли. Запись сохраняется в `ops.json`. Права задаются числовыми уровнями; см. [каталог команд](commands.md).

Записи белого списка сохраняются, но его включение хранится только в памяти: после перезапуска повторяйте `whitelist on`. **Добавление по имени вычисляет UUID без проверки аккаунта**, поэтому такой UUID не совпадает с UUID аккаунта Mojang при включённой авторизации. Блокировка использует UUID подключённого игрока, а для отсутствующего вычисляет его по имени. Выдача прав оператора использует UUID подключённого игрока. Операторы обходят белый список, но не блокировки игроков и IP.

## RCON и Query

RCON по умолчанию отключён; стандартный адрес — `127.0.0.1`. Укажите `rcon.enabled`, `rcon.address`, `rcon.port` и собственный пароль в YAML, затем перезапустите сервер. Пароль должен содержать минимум 16 байт, 8 разных байт и две категории символов. Типовые парольные фрагменты и пробелы по краям запрещены. См. [проверку пароля](../../internal/network/rcon/password.go).

RCON передаёт административные команды по TCP без TLS. Используйте доверенный интерфейс или защищённый туннель. Не добавляйте настоящий пароль в Git.

GS4 Query использует UDP и слушает все интерфейсы на `query.port`, независимо от `server.host`. Ограничьте доступ межсетевым экраном. Описание сервера и лимит игроков для Query фиксируются при старте. Ошибки запуска RCON или Query записываются в лог, но могут не остановить основной сервер. Проверяйте доступность каждой включённой службы.

## Перезагрузка настроек

- Изменения YAML отслеживаются автоматически. Без перезапуска применяются описание сервера, лимиты игроков и соединений. Остальные параметры описаны в [справочнике](configuration.md).
- `reload` загружает и компилирует датапаки. При ошибке продолжает действовать предыдущий набор ресурсов.
- Шаблоны списка игроков читаются при старте; после изменения нужен перезапуск.
- Перезагрузка по SIGHUP не настроена.

## Остановка и логирование

Используйте `stop`, SIGINT или SIGTERM и дождитесь выхода процесса. Сервер отменяет фоновые задачи, останавливает сетевые службы, закрывает сессии, дожидается выхода игроков, останавливает тики и завершает сохранение. Общий таймаут — пять секунд. Перед резервным копированием проверьте ошибки завершения.

Логи выводятся как текст или JSON. Уровень и формат задаются при старте. `logging.file_path` и `logging.enable_color` не используются при настройке логирования. Для записи в файл перенаправляйте стандартный вывод и поток ошибок средствами оболочки или менеджера процессов.

При настройке менеджера процессов задайте рабочий каталог и оставьте достаточно времени для завершения сохранений. HTTP-интерфейс метрик Prometheus/pprof сейчас не настроен.
